# Odometer algorithm (beta.7)

Fuelio's OBD trip StartOdo/EndOdo and refuel Odo become dated, numeric checkpoints. No VIN, plate, trip route or individual checkpoint list is retained in the published snapshot. A trip may cross a month boundary, so use StartDate for StartOdo when present and EndDate for EndOdo. Dates are local calendar dates from export (precision to day for aggregate purposes).

For a given calendar month or year, select the **latest day before period start**, use its highest odometer checkpoint as the baseline; select the **latest day inside the period** and its highest checkpoint as the end. The difference is observed, calendar-allocated travel. If there is no earlier baseline, choose the first day's lowest in-period odometer and mark `partial_start`, rather than claiming entire calendar coverage. Two readings needed if both endpoints are on one day. No reading in period, one endpoint only, or odometer rollback yields unavailable distance and unknown SEK/km. For the lifetime range, use first day's minimum and last day's maximum across all imported checkpoints. TripDist is a separate sanity-check statistic, never added to odometer difference.

Fuel expenditure and actual other expenditure are still *booked on transaction dates*. This cost per observed km is useful for tracking but not a fuel accrual or exact midnight-to-midnight mileage measure. A late previous-month checkpoint can assign the intervening distance to the next month; frequent OBD trip checkpoints reduce, but do not eliminate, that allocation uncertainty. No automatic Google Drive download is included.
